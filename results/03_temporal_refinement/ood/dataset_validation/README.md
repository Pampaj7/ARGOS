# OOD dataset validation

Automated physical-correctness checks on the prepared OOD data, before any benchmark
claim. Generated by the block in `evaluate`/report tooling; summary in
`servct_validation_summary.json`, per-frame numbers in `servct_sequence_metrics.csv`.

## SERV-CT — VALIDATED

All 12 checks pass (or are N/A with reason):

1. **Disparity sign plausibility** — PASS. Raw (S2M2-S) and GT disparity both > 0 on the
   valid region (positive-px, left-reference).
2. **Finite values** — PASS on the valid region.
3. **Valid-mask consistency** — PASS. Dense CT-reference masks; scanned region 100% valid.
4. **Depth↔disparity round-trip** — PASS. `fx·baseline/disp` vs GT depth: mean error a few
   mm (larger only where disparity is small, which is expected — depth ∝ 1/disp).
5. **Resize/scale correctness** — PASS. Native px preserved; `target_scale=0.25`
   valid-aware area-average, the same recipe as the training targets. No rescale to SCARED.
6. **Left/right orientation** — PASS. GT and raw both left-reference rectified.
7. **Temporal ordering** — PASS. Frame ids strictly increasing within each Experiment.
8. **Frame-count consistency** — PASS. 16 frames (8 test + 8 train); raw/GT/valid all present.
9. **GT↔raw alignment** — PASS. Identical grid after the shared downsample; raw MAE
   1.1–1.3px is physically sane.
10. **Error-distribution sanity** — PASS. Raw MAE 1.1–1.3px, Bad-3 3–8% — plausible S2M2-S
    zero-shot on clean rectified endoscopy.
11. **Random visual overlays** — see `../zero_shot_benchmark/servct/qualitative/*.png`.
12. **No future-frame leakage** — PASS. Causal window `[t, t−1, t−2, t−3]`, clamped at
    sequence start; construction verified in `build_ood_shards.py` + `FullFrameDataset`.

**Raw baseline:** test (Experiment_2) MAE ≈ 1.28px, train (Experiment_1) MAE ≈ 1.12px.

## D4D — NOT validated for dense disparity

D4D has no dense per-frame disparity GT (Zivid structured-light only, ~2 scans/session).
It is therefore excluded from the dense zero-shot disparity benchmark; see
`../dataset_discovery/missing_requirements.md` (B2). No D4D disparity metrics are produced,
so none are validated.
